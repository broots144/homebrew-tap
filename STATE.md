## What is true now

- One cask: `Casks/claudeglance.rb` at **1.8.0**, matching the latest workshop144/claudeglance release (v1.8.0, 2026-10-15). DMG URL returns 200 (checked 2026-11-06).
- `brew info --cask broots144/tap/claudeglance` resolves 1.8.0 on the operator's Mac.
- The cask is generated by the `homebrew-tap` job in workshop144/claudeglance `.github/workflows/release.yml`. It validates the tag (`^[0-9]+(\.[0-9]+){1,3}$`) and DMG sha256, clones this repo over SSH with a pinned github.com host key, overwrites the cask, and pushes to `main` as the bot identity. If `HOMEBREW_TAP_DEPLOY_KEY` is missing the release still ships and the job prints a warning. See D-002.
- Deploy keys on this repo: one, "claudeglance release (write)", read_only false, created 2026-09-27.
- `main`: ruleset "main: no force-push or deletion" active; no branch protection or required checks (D-003).
- The cask declares `depends_on macos: :ventura` (app deployment target 13.0) and `uninstall quit: "io.github.broots144.ClaudeGlance"` so upgrades and uninstalls stop the running app. The same lines are in the release.yml template on claudeglance main (merged in workshop144/claudeglance#24), so release tags keep them. Side effect: `brew upgrade` and `brew uninstall` quit a running ClaudeGlance and the cask has no relaunch step, so after an unattended upgrade the menu bar app stays closed until it is opened again (normal Homebrew behaviour, accepted).
- The build is ad-hoc signed, so the cask carries a Gatekeeper `caveats` block. release.yml drops it automatically once signing secrets exist.
- `just check` runs Ruby syntax (fails on any broken cask, not only the last), DMG URL reachability (curl bounded at 10s connect / 60s total with 3 retries; a network failure prints `000 <url>` and fails) and the STATE guard. `just style` runs `brew style` and currently reports 4 offenses (see Open).
- PR guard: `.github/workflows/state-guard.yml` runs `scripts/state-guard.sh` on pull requests only, so bot pushes to `main` are unaffected. It uses `actions/checkout` v7.0.1 pinned by SHA. The chore:/deps: escape hatch ignores merge commits (`--no-merges`), because CI checks out the PR merge ref whose "Merge X into Y" subject would otherwise always fail it.
